## 工作表定位

- 目标表：优先用户明确指定的 sheet；同时核对标题、日期和内容是否确为当批 PC 办公任务提报。
- 创作 Skill 专项：从 `workbook-info` 中寻找同一批日期、标题规范化后包含“创作skill”和“提报”的工作表。
- `sheet=` URL 参数只是稳定 ID 线索，不能拿它代替工作表清单，也不能当作创作 Skill 专项 ID。
- 候选工作表必须唯一。没有或出现多个候选时，输出候选标题与 ID，请用户消歧后再写。

## 表头别名

先 Unicode trim，再精确匹配。一个语义命中多个列时停止，不做模糊猜测。

| 语义 | 可接受表头示例 |
| --- | --- |
| 达人名称 | 达人名称、达人昵称、达人 |
| 主页链接 | 主页链接、达人主页、主页 |
| 机构 | 机构名、机构、所属机构 |
| 合作状态 | 是否合作 |
| 选题 | 选题、办公任务选题、选题方向 |
| 客户反馈 | 客户反馈、反馈、客户备注 |

别名只用于建立候选；最终必须确认该列现有内容语义一致且唯一。在 manifest 中分别记录 `headers.target` 和 `headers.creator_skill`，每个语义字段保存 `sheet_id/header/column/match_count`；创作 Skill 的 `raw_status_prewrite` 必须绑定到其“是否合作”映射，不得沿用目标表的列坐标。

## 固定达人囤积字段

固定字段顺序：

```text
达人名称、主页链接、主页去重键、平台、标签、一级行业、二级行业、
合作形式、粉丝量（万）、达人量级、机构名、原是否合作、当前状态、
首次收录日期、最近同步日期、首次来源工作表、最近来源工作表、
首次源行号、最近源行号、提报时间、预定发布日期、原选题、源表链接
```

运行时仍按表头映射，不得因这里写了顺序就硬编码列字母。字段缺失、重复或池内已有重复去重键时进入 `ANOMALY`，停止自动 upsert。

## 默认交付物

1. 一份从最新源版本原生复制的完整 spreadsheet 副本；
2. 副本目标工作表中的四段式选题；
3. 固定达人囤积的本批 upsert；
4. 一份 `[日期]-[工作表标题]-未通过明细` 飞书文档；
5. 最终执行与回读摘要。

不把上次副本或上次未通过文档当作下次写入目标；每批记录新 token 和 revision。
